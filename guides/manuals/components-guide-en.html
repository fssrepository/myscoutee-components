MyScoutee Components

Reusable Angular UI components extracted from MyScoutee: configurable forms, menus, overlays, lists, calendars, cards and media controls.

Package: @fssrepository/myscoutee-components · Version: 1.4.0 · Registry: GitHub Packages

Component catalogue · Setup · Submodule development · Release notes · License

Requirements and installation

DependencySupported peer range
Angular common/core/forms/router^21.2.0
Angular CDK and Material^21.2.0
RxJS^7.8.0
Build/test toolchainNode.js 24 and npm 11

Configure the package scope in the consuming project’s .npmrc:

@fssrepository:registry=https://npm.pkg.github.com

Authenticate using your GitHub identity and a token with read:packages, following GitHub’s npm registry instructions. Keep the token in your user-level npm configuration or CI secret, never in the repository. GitHub’s npm registry requires authentication even for public packages.

npm install @fssrepository/myscoutee-components@1.4.0

Install compatible peer dependencies in the Angular application. Supply an Angular Material theme and the Material Icons font used by mat-icon; the library does not bundle your application’s fonts, logos, themes or translation catalogue.

Component catalogue

All components below are exported from @fssrepository/myscoutee-components. Import the standalone components you use into the consuming component’s imports. Source links include the actual input/output contracts; supporting models and config types are exported through the same public API. No internal source path is needed.

Application setup

The library calls your existing adapters; it contains no MyScoutee backend, Firebase setup, domain repositories or application session.

Provider/configurationWhen to supply it
UI_TRANSLATIONS or provideUiTranslations(YourI18nService)Components that render translated labels. The contract includes revision, currentLanguage, translate and translateParams.
EXPLANATION_GUIDE_OPTIONSGuide-aware controls and overlays; configure context eligibility and loadState. Use an empty state when the application does not use guides.
Angular Router providersOverlay navigation, such as menus and popups; reuse the application’s existing router.
UI_BRANDING or the branding inputDeploymentBrandComponent. The token provides a function returning the current branding model.
UI_IMAGE_UPLOADImage uploading; provide the consumer’s upload implementation.
UI_IMAGE_DETAILSAdditional image fields or domain-specific validation.
UI_IMAGE_URLSURL variants, seeded-image conventions or a card fallback image. Default URLs pass through unchanged.
UI_LIST_DEFAULTSOverride the shared loading-window default.
FORM_FLOW_CONTROLSAdd or override form renderers; providers share a scope within one form.

A minimal translation/guide configuration for an application without a translation catalogue or guide content looks like this:

import { ApplicationConfig } from '@angular/core';
import { provideRouter } from '@angular/router';
import {
  UI_TRANSLATIONS, EXPLANATION_GUIDE_OPTIONS, type UiTranslations
} from '@fssrepository/myscoutee-components';

const translations: UiTranslations = {
  revision: () => 0,
  currentLanguage: () => 'en',
  translate: (value, fallback) => fallback ?? value ?? '',
  translateParams: (value, params, fallback) =>
    Object.entries(params).reduce(
      (text, [key, replacement]) => text.replaceAll(`{${key}}`, String(replacement)),
      fallback ?? value ?? ''
    )
};

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter([]), // Use the consuming application's routes.
    { provide: UI_TRANSLATIONS, useValue: translations },
    { provide: EXPLANATION_GUIDE_OPTIONS, useValue: {
      isExplainableContext: () => false,
      loadState: async () => ({ activeRevision: null, guideFields: [] })
    } }
  ]
};

For an existing application, bind its real translation and guide services instead. A standalone date field can then use the standard Angular value accessor:

import { Component } from '@angular/core';
import { FormsModule } from '@angular/forms';
import { DateInputComponent, type DateInputValue } from '@fssrepository/myscoutee-components';

@Component({
  selector: 'example-date-field',
  imports: [FormsModule, DateInputComponent],
  template: `<app-date-input [(ngModel)]="date"
    [model]="{ mode: 'single', precision: 'date', valueFormat: 'iso-date',
               field: { label: 'Date' } }" />`
})
export class ExampleDateField {
  date: DateInputValue = '2026-10-10';
}

Menus, routes and schedules

  • Use an AppMenu item with kind: 'toggle' and toggleStyle: 'on-off' for the on/off presentation. Existing menu events, disabled handling and form-bound selected-value arrays remain the value contract. FormFlow header toggles keep their boolean binding; no wrapper component is needed.
  • RouteInput uses a string[] value. Its popup edits a draft and commits on save. Asset assignment rules and translated domain labels belong to the consumer.
  • SlotsInput handles common schedule fields. Use scheduleOnly for a recurring task without slot rows. Supply labels, frequencyLabel and, when needed, normalizeTemplates through SlotsInputConfig. Event subdefinitions and other domain metadata remain consumer-owned.

Styles

Import shared Sass through the public package paths:

@use '@fssrepository/myscoutee-components/styles' as ui;
@use '@fssrepository/myscoutee-components/styles/contextual-colors' as colors;
@use '@fssrepository/myscoutee-components/styles/popup-close-button' as popupClose;

The root module forwards popup, motion, Material-control, form-control and SmartList-shell mixins. Additional public modules are contextual-colors, media-badge, popup-close-button and rate-card.shared. The consuming application owns global layout, theme variables and the Material theme.

Build independently

npm ci
npm run build
npm test

npm run watch rebuilds this library when its source changes. The build requires only this repository and its declared dependencies. Generated dist/, caches and node_modules/ are ignored. Component/store/helper tests live beside their owners. The root manifest is private to prevent accidentally publishing workspace sources; npm run prepare:release prepares the built dist/ manifest for publication.

Develop as a Git submodule

The source repository is myscoutee-components; the consuming directory is components:

git submodule add -b master https://github.com/fssrepository/myscoutee-components.git components

In an existing checkout:

git submodule update --init --recursive --merge components
git -C components switch master
npm ci

The consuming package declares "workspaces": ["components"] and a matching @fssrepository/myscoutee-components dependency. MyScoutee's build/serve/test entry points build this workspace before the application; its dev stack uses the existing frontend-sync process. Do not run a competing build alongside that process.

When editing a separate checkout, commit there and fast-forward the consuming submodule on master. Keep both checkouts on master. The application consumes the same implementation through the public package API; the monolith remains supported.

Releases

CHANGELOG.md and releases/ record versioned changes. Releases are built and published locally. After a completed build:

npm run prepare:release
npm pack ./dist --ignore-scripts
npm publish ./fssrepository-myscoutee-components-1.4.0.tgz --registry=https://npm.pkg.github.com

The preparation script fixes package-relative entry points, includes the license and documentation, and excludes source maps, tests and build caches from the archive. If frontend-sync is already running, use a separate copy of its completed library output in the release checkout's ignored dist/; do not run a competing build or change the output being watched by the application. Preparation replaces ng-packagr's watch timestamp version with the source manifest's release version.

Tag the verified source with vX.Y.Z, push the tag and create a GitHub Release using its versioned release notes. Attach the published .tgz and its SHA-256 checksum. GitHub Packages publication requires a local login with write:packages permission. No registry token is stored in source and no GitHub Action is required.

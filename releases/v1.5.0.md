# MyScoutee Components 1.5.0 — MSC-128

The 1.5.0 reissue consolidates components, pipes, stores, directives and scheduler
sources under one library tree. Foundation files are grouped by responsibility.
The directory-only change preserves byte-identical JavaScript and type declarations.

The subsequent loading correction restores the existing root/core star re-exports
from the pre-cleanup granular-loading source recorded in v1.4.6. Direct foundation re-exports added during
MSC-127 made lazy forms/date/gallery code eager. Public names and application
imports are preserved; no new entry points or component behavior are introduced.
Release preparation now checks the linked startup/lazy graph and all foundation
exports in split ESM output. The prior artifact fails the loading regression;
the corrected artifact passes, together with all 216 component tests.

The matching Packaging 1.5.0 reissue preserves ESM modules when executing seed
builders, avoiding missing initialization in esbuild's single-file output.
Consumer production-build and runtime qualification continues under MSC-128.

The font reissue adds an optional `styles/fonts.css` entry with the existing
Roboto 300/400/500 and filled Material Icons assets and their original licenses.
All 56 WOFF/WOFF2 files remain separate, locally served media. Both applications
consume the same exact registry artifact and regenerate the fonts during their
Pages builds instead of committing font binaries to `docs/media/`.

Font validation: all 216 component tests pass. Both consumer production builds
preserve byte-identical JavaScript, CSS and font output. Both Pages builds
regenerate all 56 fonts with local, resolvable CSS references.

The existing MSC-127 dialog changes below remain part of this version.

`DialogComponent` supports confirmation, tour and explanation configurations.
Tour target tracking and explanation sections are generic UI. Applications
provide prepared text, content, layout metadata and callbacks, and retain their
own translation, loading, preference, persistence and editor contracts.

Confirmation uses ready signal state from `DialogStore`; `DIALOG_TEXT` binds the
host's text preparation. `GUIDE_CONTEXT` connects popup registration and list
coordination without pulling application services into the package.

The package retains Angular 22.2 peers and the existing root/secondary entry
points. Release preparation validates native ESM and bundled foundation exports.

Serverless validation: library build, 15 focused component/store tests, consumer
focused tests and the main application's production build and loading groups.
Server and complete browser-flow qualification are delegated separately.

This replaces the existing 1.5.0 artifact at the user's explicit request.
